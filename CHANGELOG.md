## 0.1.0 (2026-10-11)

First public version. Phytotron is an open, simulated benchmark for greenhouse climate control built on GreenLight-Gym2 v0.2.1: fixed 60-day tomato seasons on held-out Amsterdam weather, a model-error ladder for model-based controllers, a crop-safety gate of six rules from published sources (protocol 2), and ranking of the controllers that pass on net economic value and decision time. It ships a rule-based incumbent, an economic MPC, a wrapper for RL policies, a `phytotron` command that runs the grid, rescores stored runs and accepts user controllers by name, the first simulated results (run of 10 October 2026, reported under protocols 1 and 2), and the content of growmatics.ai/phytotron. All results are simulated.

- Summaries never carry NaN: an arm without a completed season has `null` for its net value mean and standard deviation (the file was invalid JSON before; no stored result has the case), its decision time is `null` and it has no point on the Pareto front, the writer refuses NaN, and the printed summary shows `n/a`. A per-season field that some seasons have and others lack now fails the summary instead of averaging over fewer seasons than claimed.
- Configuration: every top-level block of `configs/benchmark.yaml` says which code reads it, or that it is documentation only (the protocol's own description); no key changed. `gate.method` is now checked against the one method the gate implements. A test pins the set of blocks. The comments change the config hash, so a run directory started before this change cannot be resumed (it would refuse a changed config); start a new one.
- Tests: `phytotron run` is tested end to end with a fake season runner and a serial executor (`tests/test_run_command.py`): the grid and run record it writes, resume, `--retry-failed` with the attempt history, the refusals of a changed config, changed user-controller code and a different grid, and `--rescore`. The command module now counts towards coverage.
- Site builders: the trace-derived facts on the results page take the control step and the absolute temperature limits from the configuration (the peak rule), not from the script, and skip failed seasons and records without traces. `results.json` is unchanged.
- Removed, nothing called them: `phytotron.benchmark.run_benchmark`, `Condition` and `ArmFactory` (the serial orchestrator the runner replaced), `phytotron.envs.run_season` (the harness runs every arm through `run_season_controller`), `phytotron.metrics.gate.passes_hard_gate`, `phytotron.runner.by_condition`, and the `phytotron.metrics.efficiency` module (the data-efficiency curve of a reinforcement-learning arm Phytotron does not have). Stale docstring references to files that do not exist are gone, and a test now checks that every file path mentioned in the code, the docs and the changelog exists.
- Validation: `examples/validate_mpc.py` validates the controller the benchmark runs, built through the same factory as a benchmark season (economic objective, 4-step horizon), and `PhysicsOnlyMPC.model_step` now predicts with the discretisation the optimisation problem plans with (one Radau element of degree 2 per step) instead of a finer integrator. The L2 errors in `docs/validation.md` are rerun: 0.5% on air temperature and 1.3% on vapour pressure over 6 steps, against the 0.02% the finer integrator showed for a model the controller never used. A test checks that the integrator and the hand-built collocation scheme are the same construction.
- Failed seasons: a season that fails before the controller is built (stage `setup`: configuration, simulator, reset) is listed as not started and no longer counts as a violating season; a failure while the controller is built (new stage `build`), during the season or in its checks still counts. Summaries gain `counted` on each failure and `seasons_not_started` per arm (the site's `results.json` gains the same count); `n_failed` now counts counted failures only, `n_failed_seasons` all failures. No stored result had a failure of either kind. The golden fixture is regenerated for the two new keys and gains a not-started season.
- Tests: a golden run (`tests/fixtures/run-small`, seven synthetic records: five seasons that between them break every crop-rule kind, one of them without climate traces, a controller failure with an attempt history and a season the harness could not start) must summarise to its stored `summary.json`; and the 108 season records of the run of 10 October 2026, when present locally, must rescore to the stored protocol-2 summary. Any change to what a summary reports now fails a test until the fixture is regenerated on purpose.
- Review fixes before 0.1.0: the reproduction scripts are `examples/reproduce_study_incumbent.py` and `reproduce_study_mpc.py` (the recorded run of Growmatics' forthcoming benchmark study, 24 July 2026); the de Koning (1988) citation corrected to the Acta Horticulturae paper the DOI resolves to; the run record names the pinned simulator commit when the shipped scenario files are used; `benchmark.yaml` ships inside the wheel so a non-editable install works; Python capped below 3.13 (numpy 1.x); CI tests 3.11 and 3.12; results pages mark the numbers that come from the season traces and the tolerance table says two failures from 124 seasons.
- Your own controller through the benchmark: `phytotron run --controller name=module:Class` registers a user controller as an arm (a class with a no-argument constructor, or a factory `(env, cfg, mismatch, seed)`), scored and gated like the reference arms; `--model-based` runs it on the mismatch ladder, `--seed-sensitive` runs every seed. The run record stores the module file and its hash, and a resume with changed controller code is refused. Guide: `docs/own-controller.md`.
- Protocol version 2 (`gate.protocol_version`, printed on every summary): the peak rule fails a season only when the air temperature is beyond 10 or 34 C for 30 minutes or more in a row (`min_minutes`, Körner and Challa's full-dose time); protocol 1 failed at any single step. The run of 10 October 2026 is reported under both (`results/2026-10-10-run-2/summary-protocol-2.json`); no verdict changes. Protocol history in `docs/kpis.md`.
- `phytotron` command: `quickstart`, `run` (the benchmark grid, with `--rescore`) and `fetch-weather`, with `--config` and `PHYTOTRON_CONFIG` for the benchmark configuration. The `examples/` scripts call the same code.
- Scenario files shipped: verbatim copies of GreenLight-Gym2 v0.2.1's `TomatoEnv.yml` and `rule_based.yml` with their hashes (`phytotron/scenarios/`), so a run needs no simulator checkout; `GLG2_CONFIG_DIR` is now optional. CITATION.cff added.
- Results page (`docs/results.md`): the reference controllers over the held-out seasons and the mismatch ladder, under the crop-safety rules, with the cost breakdown and what each rule found.
- Results of record: `results/2026-10-10-run-2/` keeps the run's summary, run record and grid in the repository. The website's results page (`site/content/results.md`) takes every number from `site/content/results.json`, generated from that summary by `site/build_results.py`; tests tie the docs tables and the page prose to it.
- Site figures: `site/build_rules.py` also draws the judging stages and the temperature and humidity rules to scale (`site/content/figures/`), from the configuration.
- Runner: run records store package versions, input-file hashes and arm settings; each season is checked for a full step count and in-range actions; failures record their stage; failed seasons are kept unless `--retry-failed`; a run cannot resume on another commit or config.
- Crop rules for the gate: per-season rules from the crop literature (rolling-mean temperature, a dose of extremes, a peak limit, humid hours and the longest humid run) decide the ranking. Every number traces to a published source (`docs/kpis.md`). Season records store air temperature, humidity and outdoor radiation at every step; summaries report failing-season counts, upper bounds and the night humidity deficit. The strict and banded rules stay as reported checks.
- Benchmark core: season harness, safety and efficiency metrics, a feasibility gate that runs before any ranking, Pareto ranking of net value against decision time, and a model-mismatch ladder. All benchmark constants live in `configs/benchmark.yaml`.
- Controllers: a rule-based incumbent, an economic model predictive controller (`PhysicsOnlyMPC`) on the GreenLight tomato model, and a wrapper that runs a trained RL policy through the same harness.
- Reproducibility: `phytotron.reproducibility.pin_threads()` pins the math libraries to one thread, and every run record stores the thread settings. MPC results are only reproducible with the threads pinned.
- Examples: a quickstart, weather download and build tools, MPC validation scripts, and scripts that reproduce recorded benchmark results exactly.
- Docs: quickstart, the economic MPC, and a validation page.
- CI runs ruff, mypy, the test suite and a dependency vulnerability check (pip-audit). Release tags get a CycloneDX SBOM.
- SECURITY.md: how to report a vulnerability privately.
- Project skeleton.
