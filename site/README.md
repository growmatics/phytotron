# Content for growmatics.ai/phytotron

This folder is the single source of the public Phytotron pages on the Growmatics
company site. The company site renders it; this repo owns it.

## For the company-site agent

Read this folder read-only. Never write to this repository. Never retype a number: every
number on the pages comes from `content/rules.json`, which is generated from the
benchmark configuration and checked by this repo's tests. A wording change is a request
to this repo's maintainers, not an edit on your side.

Files:

- `content/overview.md`: the page at `/phytotron/`. Front matter gives the path, the
  `<title>`, the meta description, the schema.org type and fields, and an eyebrow line.
  The body is plain Markdown with one table (the roadmap).
- `content/crop-rules.md`: the page at `/phytotron/crop-rules`. Same front matter. The
  body has three placeholders to render from `rules.json`:
  - `{{rules_table}}`: one row per rule in `gated_classes[].rules[]`, columns Class, Rule
    (`label`), A season fails when (`fails_when`), Source (each `sources[].text`
    shortened to author and year, linked to `sources[].url`).
  - `{{gate_summary}}`: from `gate`: "A controller passes a class if, with
    {confidence as %} confidence (one-sided Clopper-Pearson bound), at most
    {max_failing_share as %} of its seasons fail that class." Then one sentence per
    entry of `failing_seasons_allowed`: "With {seasons} seasons, {allowed} failing
    season(s) are tolerated." Then: "A season the controller could not finish counts as
    failing; a season the harness could not start is listed and not counted."
  - `{{sources_list}}`: every entry of `sources[]` as a reference list, `text` with `url`
    as a link.
- `content/rules.json`: the rules, the gate settings and the sources, generated by
  `python site/build_rules.py`. `generated_from.config_sha256` names the exact
  configuration it came from; show it on the crop-rules page in small print ("rules version `<first 12 characters>` · protocol `generated_from.protocol_version`") so a reader can tell versions apart.
- `content/figures/*.svg`: three figures, generated by the same script from the same
  configuration (`how-judged.svg` for the overview; `temperature-rules.svg` and
  `humidity-rules.svg` for the crop-rules page). The pages reference them as Markdown
  images with alt text, each followed by an italic caption paragraph. Inline the SVG or
  serve it as an image, unchanged: do not redraw, recolour or edit the text in them.
  Keep the alt text, render the caption as a caption, and let the figure scroll
  sideways on narrow screens rather than shrink the text below readable size.
- `content/rule_text.yaml`: the wording templates behind `rules.json`. Do not render it.
- `content/results.md`: the page at `/phytotron/results`. **Render it only when Growmatics
  names it for a build** (its front matter says when: after the code is public). Same
  front matter as the other pages. Five placeholders, all from `results.json`:
  - `{{run_setup}}`: a short definition list from `generated_from`: Phytotron commit,
    simulator, date, seasons run and failed, seasons not started (`seasons_not_started`, only when above
    zero), recorded states per season (the control steps
    plus the initial state), season length in days,
    workers, and the package versions on one line.
  - `{{verdict_table}}`: one row per entry of `verdicts`: Controller (`name`), Verdict
    seasons (`seasons`), Net value EUR/m2 (`net_mean` ± `net_sd`), then per class in
    `classes` one column "<class>: failing seasons, upper bound" rendered as
    "`failing` of `seasons`, `upper_bound`", and Gate (`gate`, with "(underpowered)"
    appended when `underpowered` is true).
  - `{{mismatch_table}}`: one row per entry of `mpc_by_mismatch`: Model error
    (`mismatch`), Seasons, Net value (`net_mean` ± `net_sd`), Fruit growth kg/m2
    (`fruit_kg_m2`), Solve success (`solve_success`), and one column per key of
    `breaks` headed by the rule's label from `rules.json` ("seasons breaking").
  - `{{money_table}}`: one row per entry of `money`: Controller (`name`, with
    "(`seasons` seasons)"), Revenue, Heating, CO2, Electricity, Net, Fruit growth
    kg/m2, Decision time ms/step (`decision_ms`), Night humidity deficit g/m3; then a
    second small table "Net value by year" with one column per key of `by_year`.
  - `{{safety_table}}`: one row per entry of `safety`: Controller, Hours outside the
    temperature band, Temperature degree-hours (C h), Worst temperature excursion (C),
    Hours above the humidity band, RH degree-hours (% h), Worst RH excursion (points),
    CO2 seasons with any excursion.
  - `{{protocol_table}}`: from `rescored` (skip the section if it is null): one row per
    entry of `arms`: Controller (`name`), Seasons, then for the rule that changed
    ("peak", label from `rules.json`) "`breaks_before.peak` → `breaks_after.peak`", Dose
    breaks (`breaks_after.dose`), Temperature class failures
    "`class_failures_before.temperature` → `class_failures_after.temperature`", Humidity
    class failures (`class_failures_after.humidity`). Head the table "protocol
    `protocol.version` → `rescored.protocol_version`".
  `trace_facts` holds the few numbers that come from the per-season climate traces (not
  in the repository); the page's prose names them and says so. Nothing to render from it.
  Print "results from run `generated_from.run`, Phytotron commit
  `generated_from.phytotron_commit`, scored under protocol `protocol.version`" in small
  print under the title.
- `content/results.json`: the numbers of the results page, generated by
  `python site/build_results.py` from `results/<run>/summary.json` in this repository.
- `content/bring-your-controller.md`: the page at `/phytotron/bring-your-controller`,
  a guide for controller authors. Plain Markdown, no placeholders. **Render it only when
  Growmatics names it for a build** (with the results page, after the code is public).
- `content/llms.txt`: text for `growmatics.ai/llms.txt` (or a section of it) and for an
  `llms.txt` entry pointing at the pages.

Rendering rules:

- Use the company theme, header, footer and navigation. Do not add "Phytotron" to the
  main navigation for now (Growmatics decides when).
- Every page says "by Growmatics" and links to the home page.
- Keep all wording as written. In particular keep "simulated" wherever it appears, and
  never add "digital twin".
- When the front matter has `faq: true`, also emit `FAQPage` JSON-LD from the page's
  "Questions" section: each bold line ending in "?" is a `Question`, the paragraph after
  it is its `acceptedAnswer` (plain text, links dropped). Render the "Progress" section as
  a plain list; its dates are absolute and stay as written.
- Emit the schema.org JSON-LD from the front matter's `schema` and `schema_fields`. For
  `crop-rules.md`, fill `citation` with every `sources[].text` and `url` from
  `rules.json`.
- Set `rel="canonical"` to `https://growmatics.ai` plus the page's `path` (no trailing slash; `/phytotron/` redirects to `/phytotron`).
- Add both pages to the site's sitemap. Make sure `robots.txt` does not block GPTBot,
  ClaudeBot, PerplexityBot or Google-Extended on these paths.
- Serve plain HTML: the pages must read fully without JavaScript.

Sync: whenever this folder changes, rebuild the pages from the new commit. Say which
commit of this repo the live pages were built from, in the page footer or in your own
deployment record.

## Approval before a deploy

1. Phytotron names a content commit (for example "content at abc1234").
2. The company-site agent builds a preview from that commit.
3. Growmatics approves the preview, naming the commit.
4. Phytotron records the approval; the company site deploys that commit.

## For this repo

- Numbers: change `configs/benchmark.yaml`, then run `python site/build_rules.py` and
  commit `rules.json` with it. `tests/test_site.py` fails when `rules.json` is stale.
- Wording of a rule: `content/rule_text.yaml`, then rebuild.
- Page text: `content/*.md`.
- Results: `python site/build_results.py` after a new run is copied into `results/`;
  `tests/test_site.py` fails when `results.json` is stale, when the run was scored under
  rules that differ from the current config, or when a number in the page's prose is not
  in `results.json`.
- Content rules: every result labelled simulated; never "digital twin"; never a
  controller product. The results page goes live only once the code that produced it is
  public, so every number points at a commit anyone can rerun.
